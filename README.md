# Schengen Visa Agent — ДЗ №1 «Агент с инструментами»

> **ВНИМАНИЕ.** Все визовые кейсы и рассчитанные сроки, доли одобрений,
> индекс сложности в этом репозитории **синтетические**. Они НЕ отражают
> текущую визовую практику. Карточки документов — ориентировочные, не
> проверены для конкретной страны и заявителя. Пользуйтесь официальными
> ссылками для актуальных требований. Реальных Telegram-выгрузок пока нет.

## Возможности первой домашней работы

- **get_visa_statistics** — агрегаты по синтетической базе (количество,
  медианные сроки, доля решений при n>=10, собственный индекс сложности).
- **get_visa_requirements** — официальные порталы и примерный общий чек-лист,
  помеченный как *непроверенный*.
- **search_visa_cases** — фильтр по стране, городу, предыдущим визам,
  до пяти **вымышленных** примеров без фиктивных Telegram-ссылок.

Провайдер выбирает вызов; harness валидирует аргументы по Pydantic,
выполняет инструменты, ограничивает количество повторов и шагов,
возвращает ошибки модели и собирает обезличенную трассу.
Все инструменты **read-only**, поэтому подтверждение изменения данных
на этом этапе не требуется. MCP не обязателен.

Полные контракты с восемью полями, сценарии ошибок и ограничения:
[docs/specification.md](docs/specification.md).

## Установка (Python 3.10+)

~~~bash
git clone https://github.com/dmamontova/schengen-visa-agent.git
cd schengen-visa-agent
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
~~~

По умолчанию в конфиге **mock**: он не использует LLM или Интернет,
а детерминированно имитирует выбор инструмента, чтобы демо
запускалось без API-ключа. Это **не** полноценное тестирование
качества выбора инструментов реальной моделью.

## Два сценария живого демо (16 ноября)

~~~bash
# 1. Успешная работа (три инструмента)
python -m schengen_agent.cli --question \
  "Франция Москва: какие документы, сколько ждать и есть похожие кейсы?" --trace

# 2. Ошибка инструмента: два искусственных таймаута поиска
python -m schengen_agent.cli --question \
  "Найди учебные кейсы подачи на визу в Италию по всем городам, сразу выполни поиск" --fault-demo --trace

# Дополнительно: приветствие, без вызовов инструментов
python -m schengen_agent.cli --question "Привет!" --trace
~~~

В режиме ошибки агент не падает, а сообщает об отсутствии ответа сервиса.
Для проверки валидации запускайте pytest:

~~~bash
pytest -q
~~~

## Подключение реальной модели

**GigaChat** (основной провайдер курса):

~~~bash
pip install -e ".[gigachat]"
# В .env:
# AGENT_PROVIDER=gigachat
# AGENT_MODEL=GigaChat-2
# GIGACHAT_CREDENTIALS=<ваш ключ>
~~~

### TLS-сертификаты GigaChat (macOS)

Если возникает `ConnectError`, причина может быть в сети или
сертификате. Проверьте доступность серверов:

~~~bash
nc -vz -G 5 api.giga.chat 443
nc -vz -G 5 ngw.devices.sberbank.ru 9443
~~~

Для доверенного подключения загрузите **Russian Trusted Root CA**
по официальной инструкции Сбера
(https://developers.sber.ru/docs/ru/gigachat/certificates).
Сохраните PEM-сертификат локально, например в
`./.certs/russian_trusted_root_ca_pem.crt`, и добавьте в **локальный**
`.env` абсолютный путь:

~~~dotenv
GIGACHAT_CA_BUNDLE_FILE=/Users/USERNAME/schengen-visa-agent/.certs/russian_trusted_root_ca_pem.crt
~~~

**Не отключайте проверку TLS** и не добавляйте сертификаты или секреты
в GitHub. Папка `.certs/` игнорируется Git. Проверьте файл командой
`openssl x509 -in .certs/russian_trusted_root_ca_pem.crt -noout -subject`.

### Если GigaChat отвечает «Модель недоступна»

Сначала обновите код: `git pull` (при SSH-клонировании),
затем запустите проверку по этапам:

~~~bash
python -m schengen_agent.diagnostics
~~~

Диагностика **не выводит ключ или сырые сообщения сервера**. Она
проверит доступность `GET /models`, простой диалог, одну минимальную
пользовательскую функцию и три инструмента проекта. GigaChat использует
упрощённое описание аргументов, при этом Pydantic проверяет реальные
аргументы при выполнении. Диагностика проверит генерацию
аргументов инструментов. При ошибке печатает только тип исключения,
HTTP-статус, если доступен, и подсказку. Если `GET /models` проходит,
а вызов с функциями не проходит, проблема, вероятно, в адаптере
или схеме инструментов, а не в логине.

Для macOS с GigaChat может потребоваться доверенный сертификат
Минцифры (см. https://developers.sber.ru/docs/ru/gigachat/certificates).
Не публикуйте `.env` и не пересылайте `GIGACHAT_CREDENTIALS`.

**OpenAI-совместимый API:**

~~~bash
pip install -e ".[openai]"
# AGENT_PROVIDER=openai
# AGENT_MODEL=<название модели>
# OPENAI_API_KEY=<ваш ключ>
# OPENAI_BASE_URL=https://api.openai.com/v1
~~~

Параметры находятся в .env (образец .env.example). **Никогда не
публикуйте ключи**. Используйте доверенный CA сертификат для HTTPS;
не отключайте проверку TLS. При использовании реальных провайдеров
нужно отдельно провести живые испытания API и проверить совместимость
версии SDK. Цикл агента при смене провайдера не меняется.

## Структура

~~~text
src/schengen_agent/
    agent.py        # общий tool-calling loop + лимиты
    providers.py    # mock, OpenAI-compatible, GigaChat
    schemas.py      # Pydantic контракты
    tools.py        # executor, ошибки, retries, fault injection
    data.py         # чтение, поиск и вычисление метрик
    config.py       # настройки
    cli.py          # интерфейс командной строки
data/
    cases.json          # синтетические кейсы
    requirements.json   # официальные порталы + шаблон списка
docs/specification.md   # спецификация, риски, тестовые сценарии
tests/                  # юнит- и интеграционные mock-тесты
~~~

### GigaChat: HTTP 422 при вызове функций

GigaChat использует более простой формат описания функций, чем JSON-схема
Pydantic. В `gigachat_compat.py` сложные конструкции `anyOf`, `default`,
`title` убираются только из отправляемых описаний функций.
Валидация в `ToolExecutor` остаётся строгой. Диагностика сначала проверяет
минимальную функцию, затем наши три инструмента. Если минимальная функция
тоже возвращает HTTP 422, возможна проблема с доступом выбранной модели
к пользовательским функциям: это отдельно указано в документации Сбера.

См. https://developers.sber.ru/docs/ru/gigachat/api/errors-description
и https://developers.sber.ru/docs/ru/gigachat/guides/functions/describing-custom-function.

### Контроль достоверности ответов

Кейсы и показатели синтетические, не представляют реальную визовую
статистику. Для вопросов о сроках system prompt предписывает использовать
`get_visa_statistics`, не выводя общие сроки из отдельных примеров.
Кроме этого, harness программно добавляет предупреждение о демонстрационных
данных к результатам после вызова любого инструмента — даже если модель
проигнорирует эту инструкцию. Если пользователь спрашивал о сроках, а
статистика не получена, harness добавляет предупреждение отдельно.
Численные утверждения LLM пока не проверяются автоматически
по источникам; на защите проверяйте их по трассе.

**Важно для демо:** город — необязательный фильтр. Агент должен вызвать
`search_visa_cases` с одной страной и искать по всем городам. Если
модель не вызовет инструмент, CLI напечатает `[DEMO NOT EXERCISED]`;
тогда таймаут не был проверен. Для живого демо формулируйте запрос
однозначно: «Найди учебные кейсы подачи на визу в Италию по всем
городам, сразу выполни поиск».

### Результаты ручной проверки реальной моделью (12 ноября 2026)

Проверено с GigaChat SDK 0.2.4 и моделью GigaChat-2:

- Многошаговый сценарий: `get_visa_requirements` → `get_visa_statistics`
  → `search_visa_cases`, все вызовы без ошибок, 4 шага модели,
  поиск вернул 3 вымышленных кейса.
- Искусственный таймаут: `search_visa_cases` вернул `timeout`;
  агент корректно сообщил о недоступности сервиса за 2 шага.
- При ручном тестировании GigaChat однажды назвал долю одобрений
  «вероятностью», а медиану — «средним». Промпт дополнен строгими
  определениями; полностью устранить такие ошибки без отдельной
  программной проверки ответа нельзя.

Для демонстрационных данных Франции: 12 кейсов, 10 положительных
решений, медиана рассмотрения 19 дней, доля 10/12 = 83.3%,
учебный индекс сложности 31.3/100. **Это не реальная статистика
французских виз**.
