# Спецификация ДЗ №1: «Агент с инструментами»

## Пользователь и задача

Гражданин РФ планирует туристическую поездку в Шенгенскую зону. Он хочет
узнать, какие источники проверять, какие документы обычно рассматривают,
каковы сроки и что можно узнать из случаев других заявителей.

Для ДЗ №1 реализован **учебный агент на локальной синтетической базе**.
Он демонстрирует работу с инструментами, но **не предоставляет
реальные оценки сроков и вероятностей одобрения**.

Долгосрочный продукт: макро-дашборд, страницы стран и чат со ссылками на
настоящие Telegram-кейсы и официальные источники. Эти функции **не входят**
в первую домашнюю работу.

## Контракты инструментов: восемь полей

| Поле | get_visa_statistics | get_visa_requirements | search_visa_cases |
|---|---|---|---|
| **Имя** | get_visa_statistics | get_visa_requirements | search_visa_cases |
| **Описание / когда** | Агрегаты и сроки, не документы и не отдельные случаи | Ссылки и примерный чек-лист, не статистика | Подбор синтетических случаев, не официальные правила |
| **Аргументы** | country: enum, city: enum/null, period_days: 30–365 | country: enum, city: enum/null | country: enum, city: enum/null, had_schengen_before: bool/null, limit: 1–5 |
| **Что не от модели** | Дата, таблица кейсов, формула | Список порталов, карточки, статус проверки | Идентификаторы, данные и поиск |
| **Результат** | Число кейсов, медианы, доля одобрений (если n>=10), индекс | Официальный URL, непроверенный общий список, статус | До 5 кейсов с датой, статусом, source_url=null |
| **Ошибки** | validation, no_data, timeout, data_error | validation, no_data, timeout, data_error | validation, no_data, timeout, data_error |
| **Тип** | Только чтение | Только чтение | Только чтение |
| **Отказ** | Нет наблюдений → честная ошибка; n<10 → нет доли/индекса | Не выдавать непроверенное за действующее | Нет совпадений → no_data; не создавать ссылок |

Допустимые country: france, italy, spain. Допустимые city:
moscow, saint_petersburg, ekaterinburg. Другие значения блокирует схема.
Типы и описание доступны модели; права и выполнение находятся в коде.

## Метрики и индекс сложности

Статистику вычисляет Python, а не LLM. Из всех кейсов в выбранном периоде:

- median_appointment_wait_days — медиана известных сроков ожидания записи;
- median_processing_days — медиана известных сроков рассмотрения;
- observed_approval_rate — отношение числа approved к числу
  known decisions (approved + refused), только если known_decisions >= 10;
- difficulty_index_0_100 — внутренний учебный индекс:

  100 × (0.40 × min(wait/60,1) + 0.35 × min(process/45,1)
  + 0.25 × (1 − approval_rate)).

При недостаточных данных индекс отсутствует. Нормировка 60/45 дней и веса
40/35/25% — **учебные допущения**, а не официальная методология.

Все кейсы в data/cases.json вымышлены и имеют source_type=synthetic_demo.
В реальном проекте требуется оценить смещение выборки Telegram: доля
публикаций об одобрении не является вероятностью одобрения всех заявок.

## Опасные действия, права и обработка ошибок

Инструменты только читают локальные данные, не записывают на подачу,
не оплачивают услуги и не отправляют заявки. Подтверждение не требуется.
При добавлении действий в будущем понадобятся проверка прав,
подтверждение конкретных параметров, журнал и ключ идемпотентности.

Аргументы проверяются Pydantic 2 (extra=forbid), ошибки возвращаются
структурированным ответом error.type/message/hint. Read-only сбои
повторяются не более одного раза. Повтор третьего одинакового вызова
блокирует harness. Максимум 6 шагов по умолчанию. Журнал хранит
название инструмента, длительность, тип ошибки и число результатов,
не хранит секреты и текст пользовательского запроса.

Текст результатов является недоверенным источником: модель не должна
исполнять инструкции из карточек или из будущих Telegram-сообщений.

## Сценарии сдачи и проверки

1. **Обычный сценарий:** «Франция Москва: какие документы,
   сколько ждать и есть похожие кейсы?» → три инструмента и
   честная оговорка о синтетических данных.
2. **Ошибка сервиса:** «Найди похожие кейсы подачи на визу в Италию»
   + --fault-demo → два искусственных таймаута, ответ без выдуманных фактов.
3. **Валидация:** period_days=999 → структурированная validation.
4. **Нет данных:** узкая комбинация country/city/experience → no_data.
5. **Нет инструментов:** «Привет!» → текстовый ответ.
6. **Малая выборка:** n < 10 → null для доли одобрений и индекса.

Уровень 1: pytest проверяет контракт и ошибки.
Уровень 2: сценарии model+tools (mock; для реального провайдера
рекомендуется повторить 3–5 раз).
Уровень 3: fault injection по --fault-demo.

## Конфигурация и границы

AGENT_PROVIDER и AGENT_MODEL задаются в .env. Поддержаны mock,
OpenAI-совместимый интерфейс и GigaChat-адаптер.
Секреты не коммитятся, .env находится в .gitignore.
MCP не используется: три локальных инструмента проще
реализовать обычными функциями (лекция 2, стр. 50).

Веб-интерфейс, автоматический импорт Telegram, живое обновление
официальных требований и настоящие модели прогнозирования — дальнейшие
этапы проекта, не реализованные в этом репозитории.
